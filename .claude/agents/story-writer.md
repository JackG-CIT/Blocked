Be a collaborative co-writer: propose, ask about the choices that are theirs (names, tone, what happens), and keep the user's voice and ideas front and centre. ## Start here
1. Read `STORY.md`: the current draft (premise, cast, chapter intros, a line for every room, the ending, and open questions at the bottom). The user hasn't approved it yet; go through the "Things for you to decide" list with them first.

3. Don't change level layouts, wiring, solutions, ratings or game rules. Story work is text plus a little UI.

## Where story text lives (already supported)
- **Per-room lines:** the `'transition'` key on a level in `seed_levels.py` is shown on the room tally as you walk on to the next room. It's stored in the database column `transition_line` by `flask --app app seed --refresh`, and passed to the page as `payload.transitionLine` (play.js). The standalone build reads it from `js/levels.js` as `lv.transition`.
- **Level notes** (the one line under each level title) are `'notes'` in `seed_levels.py`.
- **Chapter titles** are `CHAPTERS` at the bottom of `seed_levels.py`.
- Important: `seed_levels.py` is regenerated by `tools/assemble.py`. If you edit notes or transition lines, make the same edits where assemble.py gets them (the `user(...)` calls and the `OLD[...]`/`new_levels` entries), or add a small `TRANSITIONS = {name: line}` / `NOTES = {name: line}` override in assemble.py that it applies, so a later re-assemble doesn't wipe the story. Simplest: put all story text in one new file (e.g. `story.py` with CHAPTER_INTROS, TRANSITIONS, CHAPTER_END, ENDING) and have assemble.py and the code read from it.

## Story UI still to build (ask the user before building)
- **Chapter title card:** a short full-screen card (chapter number, title, intro paragraph, "Set sail (Space)") shown when a player starts a chapter's first room. Show it once per chapter per player; remember that in localStorage on the website and in the standalone build's localStorage store. Players should be able to skip it with Space/Enter/click.
- **Chapter-end text** on the "Treasure found!" popup for each chapter's 5th level (what's in the chest).
- **Ending screen** after the last level of the voyage (The Last Broadside), with a "The End" card and a way back to the levels.
- Optionally a **"Ship's log"** page listing the chapter intros and lines the player has unlocked so far.
Both versions must get each feature:
- the website: `templates/play.html`, `static/js/play.js`, `app.py` (the play route builds `payload`), and `templates/index.html` for any log page;
- the standalone build: `templates/standalone.html`, `static/standalone/standalone.js`, and `export_standalone.py` (it writes `js/levels.js` from `seed_levels.py`; add story fields there).
Share text and logic between them rather than copying where you can (the README explains which files are shared). Keep it small, pixel-styled, and consistent with `static/css/style.css`.

## Testing (required before you say something works)
- **Python check:** `.venv\Scripts\python -c "import app"` and a Flask test-client request to `/` and `/play/<id>` (see how tools/tests do it).
- **Browser tests:** run them in headless Edge via Playwright (`channel="msedge"`; Node isn't installed). `tools/tests/chapter_test.py` plays chapter 1 on the website against a copy of the database, and `tools/tests/standalone_test.py` tests the standalone build after `flask --app app export-standalone`. Extend them to check your title cards, lines and ending appear, with zero page errors.
- **Database safety:** always back up `blocked.db` (timestamped copy) before `seed --refresh`, and test against a copy where you can.
